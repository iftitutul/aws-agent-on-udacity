# Reflection

**Design decision: exact loyalty math in the AgentCore Code Interpreter.** I built `calculate_loyalty_discount` to generate a self-contained Python script and run it with `code_session(REGION).invoke("executeCode", ...)` and `clearContext=True`, rather than letting Nova Lite do the arithmetic. LLMs are unreliable with multi-step money calculations. This one has several dependent steps: points are redeemed in blocks of 500, redemption is capped at 50% of the order, the tier discount applies to the subtotal after points, and points earned depend on the product category. Encoding these rules in code makes the result deterministic and easy to audit. The tool returns `points_redeemed`, `tier_discount_pct`, `final_total`, and `remaining_points` as JSON. `clearContext=True` keeps one customer's variables from leaking into another customer's run. If the sandbox is unavailable, the tool falls back to a tier-only discount and labels the result as partial so the agent can tell the customer.

**Challenge: memory feeding back into itself.** `retrieve_customer_context` prepends a "Customer Context:" block to the user's message, and `save_support_interaction` reads that same message after the turn to write it to memory. My first version therefore stored the retrieved memories again as part of the "user query". Every session would re-save old facts and let them compound. I fixed this by keeping the original query on the hook before modifying the message and saving that text instead. A second problem was that Nova responses can start with a non-text block, such as a reasoning block. To handle this, the entrypoint returns the first content block that contains text rather than blindly indexing `content[0]`. I checked both fixes with unit tests against mocked memory and agent objects before deploying.

**Production consideration: securing the Gateway.** The project Gateway uses the NONE authorizer, so anyone with the URL can call `initiate_refund`. In production I would add a Cognito or other OIDC JWT authorizer and sign the agent's outbound MCP calls. I would also stop trusting the `customer_id` in the payload: the actor ID should come from the authenticated identity in the runtime context. Otherwise one customer could read another customer's memories or refund their orders. For cost and reliability, I would create a single `MCPClient` and tool list per container instead of per request. I would also add CloudWatch alarms on refund volume and tool error rates, and put a confirmation step or human approval in front of refunds above a set amount.
